# 项目归档与扫尾

记录 `work_root`、`final_root`，沿用用户已有约定。没有约定时，同目录输入可归档到原素材目录的 `剪辑工程/<项目版本>`；多来源归属不明时再集中对齐。工作区、原始输入、作品归档与共享环境分别管理。

## 归档

1. 清点全部项目文件，记录相对路径、大小与 SHA-256，包括素材、讲稿、图片原件、提示词、音乐乐谱、音频分轨、模型回执和恢复记录。核对在途及结果不确定的请求。
2. 复制到最终位置的独立 staging，逐文件校验后发布新版本目录。保留原始输入、既有版本；凭据和共享工具不进入作品。
3. 运行素材引用指向最终位置。普通清单与原生草稿分别维护；用户保存版使用独立副本及原生资源替换，不对加密文件做字符串替换。
4. 验证最终位置的文件、字幕、时长、素材引用、原生读取与完整预览解码。历史路径可溯源，生产引用不依赖待清理工作区。
5. 确认归档完整后，解析清理目标绝对路径并核对属于本任务，再清理已归档临时副本。未知文件和并发变化保留检查，不清理上级目录、共享环境或其他项目。

## 用户导出后关闭

用户确认导出后，找到实际成片和最后保存的注册草稿，稳定快照并逐字节核对，另存最终成片和用户保存版。先前自动预览和制作时草稿不能代替用户最终结果。完整解码最终视频，检查最新草稿全部素材，记录实际规格和验证范围。

更新 `state.json`、`handoff.json`、文件清单，分别记录成片、保存版、注册状态、用户确认、验证、归档与清理。必要文件安全归档且临时区清理结束后标记正式完结。默认普通目录，仅在明确要求时创建压缩包。
